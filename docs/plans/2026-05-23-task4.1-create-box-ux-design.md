# Task 4.1 Create Box UX Design

## Goal

Make the first Box creation path feel obvious and hard to block for a new user while keeping advanced controls available for experienced users.

## Context

Task 4 already reduced the dashboard surface area for an MVP: primary navigation focuses on Boxes, Snapshot-related entry points are hidden by config, and user-facing Sandbox copy has moved toward Box. The remaining high-friction moment is the Create Box sheet. A new user enters the Boxes page wanting to create a usable environment, but the form still exposes several advanced operational controls before they have proven the core action works.

## Design

The Create Box sheet should have a simple default path:

1. Name is optional.
2. Image is already selected with a pinned, valid default.
3. Preset images are selectable so users do not need to remember Docker image tags.
4. Resources are visible in the main form because CPU, memory, and storage are common create-time choices and keep the sheet visually balanced.
5. The Create button is reachable without understanding lifecycle, environment variables, labels, or network settings.

Advanced settings should remain available behind one collapsed section:

1. Lifecycle
2. Environment Variables
3. Labels
4. Network

Snapshot remains hidden while the Snapshot product path is incomplete. Showing a source option that the user cannot confidently choose makes the first-run journey worse than showing only the reliable Image path.

## Data Flow

When Snapshot is hidden, form defaults use `source: image` and `image: ubuntu:22.04`. Preset images write the selected image tag directly. Choosing `Custom image` reveals a single exact-tag input; the custom input is hidden again when a preset is selected. Submission keeps the current image-based create call and only includes optional advanced fields when the user has changed them. Snapshot querying remains disabled when the Snapshot source is hidden.

## Error Handling

Client validation should continue to block invalid image tags, including `latest`. API failures should continue surfacing the real error message in the toast description so users can understand whether the issue is quota, auth, billing, image availability, or backend failure.

Finish with a browser E2E pass on the local dashboard: open Boxes, open Create Box, confirm Snapshot is not visible, confirm Image defaults to Ubuntu, confirm there is only one image selector, confirm Resources are visible, confirm advanced controls are hidden until expanded, confirm preset selection still works, confirm `Custom image` reveals the exact-tag input, and confirm invalid `latest` is blocked.
